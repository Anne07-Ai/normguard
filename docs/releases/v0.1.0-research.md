# NormGuard v0.1.0 Research Snapshot

- **Tag:** `v0.1.0-research`
- **Release date:** 2026-10-21
- **Classification:** completed research evidence snapshot
- **Production status:** not approved for production retrieval use

## Purpose

This release preserves the reproducible implementation and governance evidence from
NormGuard Phase 2. It tested whether policy-first English lemmatisation improves
lexical BM25 retail retrieval without corrupting protected terminology.

This is a research snapshot, not a claim of novel algorithms, production readiness
or proven retrieval improvement.

## Included capabilities

- P0–P3 protected-term policy contracts;
- policy-first normalisation with offset-preserving span traces;
- minimal C0 and pinned spaCy C4 adapters;
- deterministic Amazon ESCI artifact and split verification;
- paired BM25 retrieval evaluation with nDCG@10;
- bootstrap confidence intervals and randomisation testing;
- terminology-safety auditing with explicit failure codes;
- two-reviewer candidate review, merge and resolution;
- guarded calibration and development orchestration;
- tamper-evident JSON, Markdown and SVG evidence reports;
- calibration diagnostics with explicit instrumentation limitations;
- locked Python dependencies and CI contract tests.

## Calibration outcome

Both experiments used 2,052 queries from the frozen ESCI calibration partition,
BM25 `k1=0.9`, `b=0.75`, seed 7 and policy SHA-256
`7eeb232eb27d1e50f6e5ab6e8519b0fd11c4454bb5cb3908a8d9fac1f339ada7`.

| Measure | v0.1.0 | v0.2.0 conservative refinement |
|---|---:|---:|
| C0 nDCG@10 | 0.812533 | 0.812533 |
| C4 nDCG@10 | 0.814379 | 0.813144 |
| Mean paired delta | +0.001846 | +0.000611 |
| CI95 | [-0.000913, 0.004656] | [-0.000811, 0.002195] |
| Randomisation p-value | 0.192581 | 0.457654 |
| Exact identifier retention | 1.000000 | 1.000000 |
| Protected-term violation rate | 0.000000 | 0.000000 |
| S0 events | 0 | 0 |
| Decision | REVIEW | REVIEW |

The pre-registered utility requirement was a mean nDCG@10 gain of at least
`+0.005` with a CI95 lower bound above zero. Neither run passed. The only
permitted refinement reduced the observed gain.

**Final decision:** STOP — general-lemmatisation utility hypothesis not supported.

The safety controls passed in both runs. Safety passing did not override the failed
utility gates. See
[ADR 0002](../adr/0002-stop-general-lemmatisation.md) for the accepted decision and
rejected alternatives.

## Data governance

- The ESCI calibration partition was used only under the frozen protocol.
- Development was not opened.
- Official-test data was not read or transformed.
- Private datasets, generated policies, reviewer files and local experiment
  artifacts are excluded from this release.
- No additional tuning against the completed calibration partition is authorised.

## Reproduce repository checks

Python 3.12 and `uv` are required.

```bash
uv sync --locked --all-extras --dev
uv run --locked ruff check src tests scripts
uv run --locked python -m unittest discover -s tests -v
```

The tests validate contracts and synthetic fixtures. Reproducing the private
calibration evidence additionally requires the independently obtained upstream ESCI
dataset and locally retained review artifacts; those files are not distributed.

## Known limitations

- One English retail dataset and lexical BM25 retrieval architecture were evaluated.
- No dense, hybrid or end-to-end RAG utility claim was tested.
- The evidence does not establish cross-domain generalisation.
- Component-level latency attribution was not instrumented.
- Descriptive subgroup effects do not replace the primary result.
- The conservative adapter remains for reproducibility, not as a production
  recommendation.

## Explicit non-authorizations

This release does not authorize:

- production deployment of general lemmatisation;
- access to the existing development or official-test partitions;
- post-hoc threshold relaxation;
- further tuning on the frozen calibration partition;
- publication of private reviewer or dataset artifacts;
- claims that NormGuard improves retrieval.

A future NormGuard Safety Core would require a separate product phase, threat model,
API contract, success criteria and release process.
