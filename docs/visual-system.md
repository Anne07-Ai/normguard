# Visual System

NormGuard uses visual design to expose evidence, decisions and failure modes.

## Identity

| Token | Value | Use |
|---|---|---|
| Ink | `#0B1220` | primary dark surface |
| Slate | `#334155` | structure and borders |
| Paper | `#F8FAFC` | readable foreground |
| Teal | `#2DD4BF` | safe, verified, selected |
| Amber | `#F59E0B` | uncertainty and review |
| Red | `#EF4444` | harmful transformation or failed gate |

The direction is precision engineering and language diagnostics. Avoid generic AI brains, robots, neon effects, decorative gradients, anime styling, and unnecessary emoji.

## Information rules

- Use a table when exact comparison matters.
- Use a diagram when relationships or sequence matter.
- Use a chart only when data supports it.
- Never encode meaning by colour alone.
- Label axes, units, sample size and uncertainty.
- Include a plain-language caption below every final figure.
- Preserve readable contrast in light and dark GitHub themes.
- Commit source data and generation code with experimental charts.

## Required visual assets

- repository banner;
- system context and evaluation-flow diagrams;
- research-gap matrix;
- safety–utility Pareto plot;
- corruption heatmap;
- latency distribution;
- benchmark dashboard screenshots;
- final paper-style result figures.

## Review gate

A visual is incomplete if the reviewer cannot answer:

1. What question does it answer?
2. Where did its data come from?
3. What conclusion is justified?
4. What conclusion is not justified?
